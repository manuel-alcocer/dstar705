Manual

QDStar for the Icom IC-705 · Windows and Linux

What QDStar is

QDStar controls an Icom IC-705 in D-STAR Terminal Mode from a Windows or Linux computer:

  • It talks to the radio over WiFi with the Icom network protocol: the control and CI-V streams, without audio. It replaces wfview for D-STAR work.
  • It has its own gateway for Terminal Mode over USB, so you do not need DStarRepeater, ircDDBGateway or any other service. It links reflectors over DPlus (REF), DCS (DCS, XLX) and DExtra (XRF).
  • It shows who is on the air, with name, location, distance and bearing, and keeps a history of every over.
  • It collects the D-PRS positions and weather reports that arrive with the voice, and manages your own D-PRS beacon.

Installation

Download the file for your system from the download section or the releases page.

Windows 10/11 (x64)

  • Installer (…-windows-x64-setup.exe): it installs QDStar for your user, with no administrator rights needed. If QDStar is already installed, the installer offers to update, reinstall or uninstall it. Updating keeps your settings, history and reflectors.
  • Portable (…-portable.zip): unzip it anywhere and run qdstar.exe.

Windows SmartScreen may warn you the first time, because the program is not signed. Choose More info → Run anyway.

Linux (x86-64 and ARM64)

There are three formats. Pick one and stick to it: they are separate installations.

FormatBest forUpdates
AppImageAny distribution, no administrator rightsFrom QDStar itself
.debDebian, Ubuntu, Linux Mint, Raspberry Pi OSInstall the new .deb
tar.gzRunning it from a folder of your choiceUnpack the new version

Not sure which architecture you have? Run uname -m: x86_64 is a PC (amd64 / x86_64 files), aarch64 is ARM64 such as a Raspberry Pi 4/5 with a 64-bit system (arm64 / aarch64 files).

AppImage

  1. Download QDStar-x.y.z-x86_64.AppImage (or -aarch64 on ARM64).
  2. Make it executable: chmod +x QDStar-*.AppImage, or tick Allow executing file as program in the file's properties.
  3. Open it with a double click or from a terminal: ./QDStar-x.y.z-x86_64.AppImage.
  4. QDStar asks Install QDStar for this user?. Choose Install: the AppImage is moved to ~/.local/bin/QDStar.AppImage and QDStar appears in the applications menu with its icon. No administrator rights are needed, and the downloaded file is gone from your downloads folder.
  5. From then on, start QDStar from the applications menu.

When a new version is out, choose Update now in the notice (see Updates): QDStar downloads it, puts it in place of the installed one and restarts. If you chose Not now, Help › Install for this user… installs it later; Don't ask again leaves the AppImage where it is, and updates then replace that file.

To remove it, use Help › Uninstall QDStar…: it deletes the AppImage, the menu entry and the icon. Your settings, history and reflectors are kept.

If the AppImage does not start, your system may lack FUSE. Install it (sudo apt install fuse3 on Debian and Ubuntu), or run it with ./QDStar-*.AppImage --appimage-extract-and-run.

.deb

Install it with sudo apt install ./qdstar_x.y.z_amd64.deb (or _arm64.deb). apt pulls in the libraries it needs, and QDStar appears in the applications menu and as the qdstar command. To update, install the new .deb the same way; to remove it, sudo apt remove qdstar.

tar.gz

Unpack it wherever you like (tar xzf QDStar-x.y.z-linux-amd64.tar.gz) and run qdstar/qdstar. It adds nothing to the applications menu. To update, unpack the new version over the old folder.

USB access for EXT mode

For EXT mode your user needs access to the radio's USB serial ports: sudo usermod -aG dialout $USER on Debian, Ubuntu and Raspberry Pi OS, or the uucp group on Arch. Log out and back in afterwards.

The ARM64 builds run on Raspberry Pi OS bookworm, Debian 12 or later and Ubuntu 22.04 or later.

Radio setup

Network (both modes)

  1. Connect the IC-705 to your WiFi network (SET › WLAN Set) and give it a fixed IP address, or reserve one in your router.
  2. In WLAN Set › Remote Settings, set Network Control to ON and create a Network User with a user name and password.

INT mode: internal gateway over WiFi

  1. DV GW › Gateway Select: Internal Gateway (WLAN).
  2. DV GW › Internal Gateway › Gateway Repeater (Server/IP/Domain): your G3 Terminal Mode server, for example server1.dstar.es.
  3. Terminal/AP Call Sign: your call sign with Z in the 8th position (EA7KLX Z).
  4. Turn Terminal Mode on (MENU › DV Gateway › Terminal Mode).

EXT mode: QDStar's gateway over USB

  1. Connect the radio's USB cable to the computer.
  2. DV GW › Gateway Select: External Gateway USB (B).
  3. Terminal/AP Call Sign: your call sign with B in the 8th position (EA7KLX B).
  4. Turn Terminal Mode on.
REF reflectors use DPlus, which only accepts call signs registered in the D-STAR trust network (regist.dstargateway.org). DCS, XLX and XRF reflectors need no registration.

First run

The first time, QDStar opens the settings. Enter the radio's IP or host name, the network user and the password you created on the radio, and press Save. QDStar connects and reads your call sign from the radio (MY call sign). You do not need to type it.

QDStar also imports the connection details from wfview if they are there. Only one QDStar runs at a time: opening it again brings the running window to the front.

The main window

The window is narrow and tall so that it fits next to other programs. Its width is fixed, and you can make it taller to see more history.

The reflector screen

The black screen shows, from top to bottom:

  • The reflector: name, description, whether it is online, the number of connected nodes and the link state.
  • The station on the air, or the last one heard. It shows the call sign, the name and location from radioid.net, and the over's message and duration. When the station sends a D-PRS position, a box shows the distance and bearing from you.
  • Last heard on the reflector: the latest stations, from the reflector's dashboard or from your history.
  • The footer shows your call sign, your locator (when the radio knows your position), whether you send D-PRS, and the clock.

Mode, reflector and tabs

Below the screen are the INT · WiFi and EXT · USB/PC buttons, with a LED on the active one. A ⚠ sign appears when the radio does not match the chosen mode, for example when the radio is still in INT while you chose EXT. Hover over it to see what to check.

Next come the reflector list with its buttons, and the History, Log, D-PRS and Weather tabs.

Change mode with the two buttons. Remember to change Gateway Select and the Terminal/AP Call Sign on the radio too (see Radio setup).

In EXT mode, QDStar remembers the reflector you were linked to and links it again the next time it starts.

Reflectors

The list comes with a selection of reflectors. Manage it in Reflectors › Manage…:

  • Type: INT (the TO is written to the radio) or EXT (linked by QDStar's gateway).
  • TO / reflector: in INT, the TO the radio sends (/XLX214D). In EXT, the reflector and module (REF001 C, DCS214 D, XLX048 A, XRF988 D).
  • Server: INT only. It is the G3 server that leads to that TO. QDStar warns you when it does not match the one in the settings.
  • Name and Description: the texts shown on the screen.
  • Dashboard and API (optional): the reflector's web page and its xlxd JSON API, used for the node count and the last heard list.

Reflectors › Refresh status asks every reflector for its state straight away.

History and log

The History tab lists every over, received (RX) and transmitted (TX): time, call sign, distance, name, reflector, duration, message and location. A name or message that arrives after the over has ended is filled in on its row. History › Clear history… deletes it.

The Log tab shows what the application is doing: connections, links, errors. Radio › Log RX/TX CI-V frames adds the raw CI-V traffic, which is useful when reporting a problem.

D-PRS and weather

Received reports

Many stations send their position (D-PRS) with each over. QDStar reads it from the radio and shows the distance and bearing on the screen and in the history.

The D-PRS tab lists every report received: positions, objects, items and weather reports. That includes the ones relayed by other stations, such as the APRS gateways that repeat reports into D-STAR, and the Via column says which station carried each one.

The Weather tab shows a card for each weather station heard, with its temperature, humidity, pressure, rain and wind.

You can hide both tabs in the settings. The position of the station on the air is still shown either way.

Your own position

Radio › D-PRS position… reads and changes the radio's D-PRS settings over CI-V:

  • Send my position with every over: turns the D-PRS beacon on or off (GPS TX Mode = D-PRS).
  • Position source: the radio's internal GPS, or a manual position.
  • Manual position: latitude and longitude in degrees (west negative), with an optional altitude. Use locator fills them in with the centre of a grid square, so you announce an area rather than your exact home.
  • Symbol, SSID and Comment of your beacon.

QDStar uses your position, from the GPS or the manual one, to work out the distances. Nothing is written to the radio until you press Save.

Settings

Open them from Radio › Settings…. Changes apply when you press Save. If you change the language, QDStar uses it from the next start.

Updates

QDStar checks GitHub for a new version on start-up and once a day. When one is out, a ⬆ New x.y.z link appears next to the mode buttons, pointing at the right file for your system. You can also check by hand in Help › Check for updates…, and turn the automatic check off in the settings.

With the Linux AppImage, Update now downloads the new version, checks it against the SHA-256 published on GitHub, puts it in place of the one you run and restarts QDStar. There is no file to replace by hand.

Troubleshooting

The Icom LED never turns green

  • Check the IP, user and password, and that Network Control is ON on the radio.
  • Only one program can hold the radio's network session. Close wfview, RS-BA1 or any other remote control software.

The radio refuses the connection after a crash

Close QDStar before switching the radio off, so it ends the network session cleanly. A session left open can keep the radio's network server busy until the radio is power cycled.

EXT mode: the USB LED is red

Check the cable, and on Linux check that your user is in the dialout (or uucp) group. If the data port is not found, choose it by hand in the settings.

A REF reflector does not link

DPlus needs your call sign registered in the D-STAR trust network. Try a DCS or XLX reflector to confirm everything else works.

⚠ next to the mode buttons

The radio's Terminal Mode does not match the mode chosen in QDStar. Hover over it to see what to change on the radio.

Contributing

  • More reflectors: open a pull request adding entries to qdstar/default_reflectors.json.
  • New languages: copy qdstar/translations/es.po to your language's code, translate it and open a pull request. The README explains how.
  • Bugs and ideas: open an issue on GitHub.

QDStar is free software (GPL-3.0-or-later). The Icom network protocol is reimplemented from wfview. The Terminal Mode, DPlus, DCS and DExtra code is ported from G4KLX's DStarRepeater and ircDDBGateway.
